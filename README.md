# คลังวิธีแก้ปัญหา HIS

เว็บรวบรวมปัญหาที่ User แจ้งบ่อย พร้อมสาเหตุและขั้นตอนแก้ไข ใช้ภายในเครือข่ายโรงพยาบาล

- **คนทั่วไป (ไม่ Login)** ค้นและดูได้เฉพาะเรื่องที่ติ๊ก "เปิดให้ User เห็น"
- **ทีม (Login)** เห็นทุกเรื่อง เพิ่ม แก้ไข ลบ แนบรูป และ Export ข้อมูลได้
- **ผู้ดูแลระบบ** ทำได้ทุกอย่างของทีม + จัดการผู้ใช้ + Import ข้อมูล

## ติดตั้งและเปิดใช้

ต้องมี Node.js 22.13 ขึ้นไป (ใช้ SQLite ที่มากับ Node ไม่ต้องติดตั้ง Visual Studio)

**วิธีง่าย (Windows):** ดับเบิลคลิก `start.bat`
ครั้งแรกจะติดตั้งให้เอง (ต้องต่ออินเทอร์เน็ต) แล้วเปิดเบราว์เซอร์ให้อัตโนมัติ ปิดหน้าต่างดำเพื่อหยุดการทำงาน

**วิธีพิมพ์คำสั่ง:**

```bash
cd his-kb
npm install
npm start
```

หน้าต่าง Console จะแสดงลิงก์สำหรับเครื่องนี้และลิงก์ IP สำหรับให้เพื่อนในทีมเปิด

**บัญชีตั้งต้น:** ชื่อผู้ใช้ `admin` รหัสผ่าน `admin` (ใช้ร่วมกันทั้งทีมได้) แต่ละคนสร้างบัญชีของตัวเองเพิ่มได้ที่ บัญชี > จัดการผู้ใช้ ระบบจะใส่ข้อมูลตัวอย่าง 4 เรื่องให้ตอนรันครั้งแรก แก้หรือลบได้

## ดึงเคสจากระบบรับแจ้งปัญหาอัตโนมัติ (API)

ใช้ API รายงานสรุปปัญหา (`GET .../api/v1/reports/case-summary`) ตัวเดียวกับที่หน้า Report > สรุปปัญหา รพ.สต. ของระบบรับแจ้งปัญหาใช้อยู่

1. Login ด้วยผู้ดูแลระบบ > บัญชี > **เชื่อมต่อระบบรับแจ้งปัญหา (API)**
2. วาง token: เปิดหน้า Report ของระบบรับแจ้งปัญหา > F12 > Network > กด "แสดงรายงาน" > คลิก `case-summary` > Headers > Request Headers > `Authorization` คัดลอกค่าหลังคำว่า `Bearer`
3. ใส่ **URL ของ API** (ดูได้จากช่อง Request URL ในขั้นตอนเดียวกัน) เลือกรอบเวลา แล้วกด **บันทึกและดึงข้อมูลตอนนี้**

- เครื่อง Server ต้องออกอินเทอร์เน็ตไปที่ระบบรับแจ้งปัญหาได้
- API ส่งเคสทั้งหมดทุกครั้ง ระบบจึง**แทนข้อมูลเคสเดิมทั้งหมด** เคสที่แก้ไขในต้นทางจะอัปเดต เคสที่ถูกลบจะหายไป (เคสที่นำเข้าจาก Excel ก่อนหน้าก็จะถูกแทนด้วย)
- ถ้าดึงไม่สำเร็จหรือได้ข้อมูลว่าง ข้อมูลเดิมยังอยู่
- ได้ช่อง `root_cause` (สาเหตุ), `agency_code` (รหัสหน่วยงาน 5 หลัก) และ `case_no` (เลขเคส) เพิ่มจาก Excel
- **ไม่เก็บ** `reporter_name` และ `anydesk_id`
- token ส่วนตัวมีวันหมดอายุ หน้านี้แสดงวันหมดอายุ และเตือนที่หน้าแรกและหน้าภาพรวมปัญหาเมื่อหมดอายุ ให้วาง token ใหม่ ถ้าได้ API Key ถาวรจากผู้ดูแลระบบรับแจ้งปัญหา ให้วางในช่องเดียวกัน
- token เก็บในไฟล์ `data/kb.sqlite` บนเครื่อง Server อย่าแชร์ไฟล์นี้

## เคสที่เคยแก้ (นำเข้าจากระบบรับแจ้งปัญหา)

1. Export รายงานเคสจากระบบรับแจ้งปัญหาเป็นไฟล์ `.xlsx` (แบบ "สรุปปัญหา รพ.สต.")
2. Login ด้วยผู้ดูแลระบบ > บัญชี > **นำเข้าเคสจาก Excel** > เลือกไฟล์
3. ทีมพิมพ์ปัญหาที่ User แจ้งในช่องค้นหา ระบบแสดง **วิธีแก้ที่แนะนำ** ก่อน (จากบทความ หรือวิธีที่ทีมใช้บ่อยในเคสที่คล้ายกัน) กด **คัดลอกขั้นตอนส่ง LINE** ได้ทันที เคสที่คล้ายกันอยู่ด้านล่าง

สิ่งที่ระบบทำตอนนำเข้า
- อ่านคอลัมน์ วันที่, เลขเคส, โครงการ, รายละเอียดปัญหา, แนวทางการแก้ไข, ผู้ดำเนินการ, ระยะเวลา, ประเภทปัญหา, สถานะ และ **สาเหตุ** (ถ้ามี)
- เก็บเฉพาะเคสที่ปิดแล้ว ข้ามเคสที่วิธีแก้เขียนแค่ "ใช้งานได้แล้ว" หรือ "ติดต่อไม่ได้"
- **ไม่เก็บชื่อผู้แจ้ง** และลบเบอร์โทร, เลข AnyDesk, LINE ID ออกจากข้อความ
- นำเข้าไฟล์ซ้ำหรือไฟล์ที่ช่วงวันที่ทับกันได้ เคสเดิมจะไม่ถูกเพิ่มซ้ำ แนะนำให้นำเข้าทุกสัปดาห์หรือทุกเดือน

การค้นหาเรียงตามความคล้ายของข้อความ และถือว่าคำที่สะกดต่างกันเป็นคำเดียวกัน เช่น ปริ้น/ปริ๊น/พิมพ์, สติ๊กเกอร์/สติกเกอร์, สิทธิ/สิทธิ์, ไม่ได้/ไม่สามารถ เพิ่มคำได้ที่ `public/norm.js`

เมนู **ภาพรวมปัญหา** (หน้าแรกแสดง 6 เรื่องที่เจอบ่อยใน 7 วัน) จัดกลุ่มเคสที่คล้ายกันและเรียงตามจำนวน พร้อมวิธีแก้ที่ใช้บ่อยที่สุด กด **สร้างบทความ** เพื่อดึงข้อความเป็นร่างบทความ แล้วเติมขั้นตอนและรูปประกอบ

เคสเก่าเห็นได้เฉพาะทีมที่ Login เท่านั้น

## เขตสุขภาพ / จังหวัดของเคส

ตารางจังหวัด → เขตสุขภาพ (13 เขต) อยู่ในระบบแล้ว ไม่ต้องเชื่อม API ส่วนรหัส 5 หลัก/ชื่อ รพ.สต. → จังหวัด ใช้ไฟล์รายชื่อสถานพยาบาล:

1. Login ด้วยผู้ดูแลระบบ > บัญชี > **นำเข้ารายชื่อสถานพยาบาล**
2. ไฟล์ .xlsx หรือ .csv ต้องมีคอลัมน์ รหัส 5 หลัก (`รหัส`, `hcode`, `hospcode` ...), ชื่อ (`ชื่อหน่วยบริการ`, `name` ...) และจังหวัดเป็นชื่อหรือรหัส 2 หลัก (`จังหวัด`, `changwat`, `chwpart` ...) เช่น Export ตาราง `hospcode` จาก HOSxP
3. ไฟล์ใหม่แทนรายชื่อเดิมทั้งหมด และจับคู่เคสทั้งหมดใหม่ให้อัตโนมัติ

ลำดับการหาพื้นที่ของแต่ละเคส (แม่นที่สุดก่อน)
1. **รหัส 5 หลัก** ที่พิมพ์มาในเคสและมีอยู่ในรายชื่อ (ถ้าเคสระบุจังหวัดไว้แล้ว รหัสต้องอยู่จังหวัดเดียวกัน กันการจับรหัสค่าบริการผิด)
2. **ชื่อ รพ.สต.** ที่ตรงกันเพียงแห่งเดียว (ชื่อซ้ำหลายจังหวัดจะใช้จังหวัดของเคสช่วยเลือก)
3. **คอลัมน์จังหวัด** ในไฟล์เคส
4. **จังหวัดในช่องทางรับแจ้งหรือโครงการ** เช่น "SSO พิษณุโลก" แสดงป้าย "ประมาณการ"

ในหน้าภาพรวมปัญหา เลือกกรองตามเขตและจังหวัดได้ รวมถึง "ไม่ทราบพื้นที่"

## เวอร์ชันทดลอง (GitHub Pages)

หน้าเว็บแบบไม่มี Server ให้ทีมลองใช้ผ่านลิงก์ ข้อมูลเคสเป็นตัวอย่างที่แต่งขึ้น (`demo/demo-data.js`) และสิ่งที่บันทึกเก็บเฉพาะในเบราว์เซอร์ของแต่ละคน

```bash
node scripts/build-demo.js demo-site
```

repo นี้เก็บเวอร์ชันทดลองไว้ในโฟลเดอร์ `docs/` (สร้างด้วย `node scripts/build-demo.js docs`) เปิดที่ Settings > Pages > Deploy from a branch > `main` > `/docs`
ห้ามใส่ข้อมูลเคสจริงในเวอร์ชันทดลอง เพราะทุกคนที่มีลิงก์เปิดดูได้

## เปิดให้ทีมเข้าจากที่ไหนก็ได้ (Cloudflare Tunnel)

ดับเบิลคลิก `start-online.bat` บนเครื่องที่เก็บข้อมูล ไฟล์นี้จะ
1. เปิด Server (หน้าต่าง "HIS-KB Server")
2. ติดตั้ง `cloudflared` ให้ครั้งแรกผ่าน winget (ถ้ายังไม่มี)
3. สร้างลิงก์ `https://xxxx.trycloudflare.com` ให้ส่งต่อทีม

- ลิงก์ใช้ได้ตราบที่เครื่องเปิดและหน้าต่างยังไม่ถูกปิด เปิดใหม่จะได้ลิงก์ใหม่
- ต้องการลิงก์ถาวร: ใช้ Cloudflare Tunnel แบบมีบัญชีและโดเมน หรือย้ายไปเครื่อง Server/Cloud
- บัญชีที่ยังใช้รหัส `admin` และบัญชีที่ admin สร้างหรือรีเซ็ตรหัสให้ ต้องตั้งรหัสใหม่เองตอน Login ครั้งแรก
- จำกัดการใส่รหัสผิด 5 ครั้งแยกตามผู้ใช้แต่ละคน (อ่านจาก header ของ Cloudflare)

## ตั้งค่า (ผ่านตัวแปร Environment)

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `PORT` | `3000` | พอร์ตของเว็บ |
| `HOST` | `0.0.0.0` | ใช้ `127.0.0.1` ถ้าจะให้เข้าได้จากเครื่องนี้เท่านั้น |
| `DATA_DIR` | `./data` | ที่เก็บฐานข้อมูลและรูป |
| `COOKIE_SECURE` | ไม่ตั้ง | ตั้งเป็น `1` เมื่อเปิดผ่าน HTTPS |

Windows (PowerShell): `$env:PORT=8080; npm start`

## ให้รันตลอดเวลา (Windows Server)

ใช้ PM2:

```bash
npm install -g pm2 pm2-windows-startup
pm2 start server.js --name his-kb --node-args="--disable-warning=ExperimentalWarning"
pm2 save
pm2-startup install
```

ดู log: `pm2 logs his-kb` / รีสตาร์ต: `pm2 restart his-kb`

อย่าลืมเปิด Firewall พอร์ต 3000 ให้เครื่องในเครือข่ายเข้าได้

## สำรองข้อมูล

ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `data/`

- `data/kb.sqlite` ฐานข้อมูล (ปัญหา ผู้ใช้ คะแนน ประวัติการแก้ไข)
- `data/uploads/` รูปประกอบ

สำรองโดย copy ทั้งโฟลเดอร์ `data/` (แนะนำให้หยุด Server ก่อน หรือ copy ไฟล์ `kb.sqlite-wal` ไปด้วย)
หรือใช้เมนู **บัญชี > ดาวน์โหลดข้อมูลสำรอง** ได้ไฟล์ JSON ของปัญหาทั้งหมด (ไม่รวมรูป)

## จัดการผู้ใช้

- ผ่านหน้าเว็บ: Login ด้วยผู้ดูแลระบบ > บัญชี > จัดการผู้ใช้
- ผ่านคำสั่ง (ใช้กู้บัญชีเมื่อลืมรหัส):

```bash
npm run create-user -- somchai รหัสผ่าน8ตัว team สมชาย ใจดี
npm run create-user -- admin admin
```

ถ้าชื่อผู้ใช้มีอยู่แล้ว คำสั่งนี้จะเปลี่ยนรหัสผ่านให้แทน

## ย้ายข้อมูลจากเวอร์ชันบน Claude

1. ขอไฟล์ JSON ของข้อมูลจาก Claude
2. Login ด้วยผู้ดูแลระบบ > บัญชี > นำเข้าข้อมูล > เลือกไฟล์
3. เรื่องที่มีรหัสเดียวกันจะถูกอัปเดต เรื่องใหม่จะถูกเพิ่ม

## กู้คืนเรื่องที่ลบหรือแก้ผิด

ทุกครั้งที่แก้ไขหรือลบ ระบบเก็บข้อมูลเดิมไว้ในตาราง `article_history` เปิดดูด้วยโปรแกรม SQLite (เช่น DB Browser for SQLite) แล้ว copy ค่าในคอลัมน์ `data` ไป Import กลับได้

## โครงสร้างไฟล์

```
server.js            API และเว็บ Server
db.js                ตารางฐานข้อมูลและฟังก์ชันอ่าน/เขียน
cases.js             นำเข้าเคสจาก Excel, ค้นหาเคสคล้ายกัน, จัดกลุ่มปัญหาที่พบบ่อย
sync.js              ดึงเคสจาก API ของระบบรับแจ้งปัญหาตามรอบเวลา
locations.js         จังหวัด/เขตสุขภาพ, นำเข้ารายชื่อสถานพยาบาล, จับคู่พื้นที่ของเคส
scripts/create-user.js
start.bat            ดับเบิลคลิกเพื่อเปิดใช้งาน (Windows)
start-online.bat     เปิดใช้งาน + ลิงก์ https ให้ทีมเข้าจากนอกเครือข่าย
seed-data.json       ข้อมูลตัวอย่างที่ใส่ตอนรันครั้งแรก
public/              หน้าเว็บ (index.html, app.js, style.css)
data/                ฐานข้อมูลและรูป (สร้างอัตโนมัติ)
```

## API

ทุกคำขอที่ไม่ใช่ GET ต้องส่ง Header `X-KB: 1`

| Method | Path | สิทธิ์ |
|---|---|---|
| POST | `/api/login`, `/api/logout` | ทุกคน |
| GET | `/api/me` | ทุกคน |
| GET | `/api/articles` | ทุกคน (ไม่ Login เห็นเฉพาะเรื่องที่เปิดให้ User) |
| POST / PUT / DELETE | `/api/articles[/:id]` | ทีม |
| POST | `/api/articles/:id/feedback` `{value: 1, -1, 0}` | ทุกคน |
| POST | `/api/uploads` (body เป็นไฟล์รูป) | ทีม |
| GET | `/api/export` | ทีม |
| POST | `/api/import` | ผู้ดูแลระบบ |
| GET / POST / DELETE | `/api/users[/:id]` | ผู้ดูแลระบบ |
| PUT | `/api/users/:id/password` | ตัวเอง หรือผู้ดูแลระบบ |
